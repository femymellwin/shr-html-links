Simple Docker & Kubernetes Troubleshooting Practice

60 interview questions. Type one command at a time. No dashboards or complex navigation.

Every question follows the same five steps: Start healthy → Break it → Find the cause → Fix it → Check recovery.

Scope: 10 Docker + 50 Kubernetes exercises. Most use one disposable Kind cluster. Optional Ingress, metrics, NetworkPolicy and actual node DiskPressure have clearly stated prerequisites or limitations. No commands were live-tested against Docker in the document-generation environment.

Part 1. Install only once

Choose one of these computers. After installation, everyone runs the same commands in a Bash terminal.

A. Mac laptop

Install Docker Desktop for Mac and start it. Install Homebrew from brew.sh if needed. Open Terminal and type:

1.brew install kind kubectl
2.docker version
3.kind version
4.kubectl version --client

B. Windows laptop

Open PowerShell as Administrator, type the next command, then restart if prompted:

1.wsl --install -d Ubuntu

Install Docker Desktop for Windows; enable its WSL 2 backend and Settings → Resources → WSL Integration → Ubuntu. Use Linux containers, not Windows containers. Open the Ubuntu (WSL) terminal, NOT PowerShell, for all subsequent practice commands.

2.sudo apt update
3.sudo apt install -y curl ca-certificates unzip

Unzip the project into your Ubuntu home folder. The file install-linux-tools.sh is inside it. From the project folder:

4../install-linux-tools.sh
5.docker version

C. Ubuntu Linux VM, including an Azure Ubuntu VM

Use Ubuntu 22.04/24.04 on a disposable VM with roughly 4 vCPUs, at least 8 GB RAM and about 30 GB free space. SSH to the VM. Do not expose Docker or Kubernetes API ports to the internet.

1.sudo apt update
2.sudo apt install -y docker.io curl ca-certificates unzip
3.sudo systemctl enable --now docker
4.sudo usermod -aG docker "$USER"
5.newgrp docker

Unzip the project and change to its folder, then:

6../install-linux-tools.sh
7.docker version

Cloud VMs can incur charges until deleted. This exercise uses Kind inside Docker on the VM; it does not create Azure AKS or AWS EKS.

All three computers: create your first Kubernetes cluster

Keep the terminal inside the unzipped project folder. Ensure Docker is running. Start with these four commands, one by one:

1../lab setup
2.kubectl get nodes
3.kubectl -n practice get pods
4.kubectl -n practice get services

You should see one control-plane node, two workers, a Running / Ready web Pod and a web Service. It may take a minute on the first run. The script creates only the cluster named interview-lab.

When you complete any Kubernetes question: type ./lab reset to restore the healthy app before starting a different question. For Docker questions, ./lab prepare DCK-001 (with the ID you want) also restores a healthy baseline.

Six commands to remember

  • docker ps -a: Which containers stopped or restarted?
  • docker logs NAME: What did the application print?
  • kubectl get pods: Running, Pending, or CrashLoopBackOff?
  • kubectl describe pod: Why is Kubernetes unhappy? Read Events.
  • kubectl logs: What error did the process produce?
  • kubectl rollout status: Did the repaired release become Ready?

Safety: Do not run fault-injection commands against work, customer, AKS, EKS or production clusters. Before every Kubernetes exercise, type kubectl config current-context and confirm it says kind-interview-lab. All exercises except the clearly labeled extra CNI/VM cases are designed for that disposable cluster. A failed command in the "Break" section is often the expected symptom—continue with "Find".

Question 1. Container stops after starting DCK-001

Interviewer: "Container stops after starting. How would you investigate and recover?"

Where: Local lab

1.docker ps

Use this short answer for almost every outage: “I check the failing resource and its events first. Then I check application logs and the network or storage path. I identify the exact root cause, change only what is needed, and verify the Pod and the user-facing service are healthy.”
