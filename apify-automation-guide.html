Automated Job Discovery & Application Pipeline

A practical implementation guide using Apify + n8n + a CV-matching step + a controlled application worker. Designed to automate discovery and preparation, while only auto-submitting on sites where automation is permitted.

1. The recommended operating model

The reliable version is not "scrape every job and blindly click Apply." It is a controlled funnel:

Scrape jobs
->
Normalize
->
Deduplicate
->
CV match
->
Prepare answers
->
Approval / policy gate
->
Apply
->
Log outcome
Recommended default: automate everything up to the final submission. Auto-submit only for an allowlist of employer/ATS sites whose terms permit it and where every required answer is known with high confidence.
LinkedIn: do not build a LinkedIn scraping or auto-application bot. LinkedIn's current User Agreement prohibits software/scripts/robots used to scrape or copy its services and prohibits bypassing security/access controls. Keep LinkedIn in manual/review mode.

2. Architecture

1. Job collectorsApify Naukri/public-job Actors, company career pages, or other permitted public sources.
2. Orchestratorn8n receives the Apify webhook, processes each row, calls scoring services, and controls the workflow.
3. Job databasePostgreSQL, SQLite, Airtable, or Google Sheets for duplicate prevention and application history.
4. Candidate profileA structured JSON file containing your real experience, skills, notice period, locations, salary preferences, and standard answers.
5. Matching engineRules + optional LLM score each role against your CV and reject jobs outside your constraints.
6. Apply workerPlaywright or an ATS/API integration. It must fail closed on CAPTCHA, unknown questions, login challenges, or unsupported domains.

3. Set up Apify

1
Create a job-search Actor task.

Choose a Naukri/public jobs Actor from Apify Store, test it manually, then use Save as a new task. Apify tasks are reusable Actor configurations that can be run manually, by schedule, or by API.

2
Use narrow searches.

Create separate searches for your main target titles instead of one extremely broad query.

{
  "searchQueries": [
    "DevOps Engineer",
    "Cloud Engineer",
    "Platform Engineer",
    "Site Reliability Engineer"
  ],
  "locations": ["Dubai", "Abu Dhabi", "United Arab Emirates"],
  "maxJobs": 50,
  "freshness": "7",
  "scrapeJobDetails": true
}

Actor input field names differ by Actor. Copy the actual JSON schema from the Actor's Input/API tab.

3
Schedule the task.

In Apify Console: Schedules -> Create new -> Add -> Actor task. Start with twice daily rather than every few minutes. Apify supports cron schedules and timezone settings.

# Example: 08:00 and 18:00 every day
0 8,18 * * *
4
Create an n8n Webhook URL.

In n8n, add a Webhook node, use POST, and copy its production URL.

5
Add the Apify webhook.

Configure the Actor/task so ACTOR.RUN.SUCCEEDED posts to the n8n Webhook URL. Apify webhooks are intended for triggering downstream HTTP actions when a run succeeds or fails.

5. Match jobs to your CV before applying

Use hard filters first, then a weighted fit score. This prevents the automation from wasting applications on roles that are obviously unsuitable.

SignalExample weightRule
Target job title25%DevOps / Cloud / Platform / SRE variations.
Required technical skills30%AWS, Terraform, Kubernetes, Linux, CI/CD, etc.
Years / seniority15%Reject large gaps rather than inventing experience.
Location / remote mode10%Must match your real preferences.
Domain / responsibilities10%Infrastructure, operations, platform engineering, SRE.
Salary / notice period10%Use only if the posting provides enough information.
Example routing:
Score < 65 -> reject automatically
65-79 -> save for review
80-89 -> prepare application + request approval
90+ -> eligible for auto-submit only if the domain is allowlisted and every required answer is known

The candidate profile should contain only facts you have approved. Never let the model invent years of experience, certifications, salary, work authorization, security clearance, education, or questionnaire answers.

6. Application worker: Playwright pattern

For an employer site or ATS where browser automation is permitted, use a separate Playwright worker. Keep credentials and CV files outside n8n workflow JSON.

Fail-closed submission design

// illustrative Node.js / Playwright skeleton
import { chromium } from 'playwright';

const AUTO_SUBMIT = process.env.AUTO_SUBMIT === 'true';
const ALLOWLIST = new Set([
  // Add only domains whose current terms/process allow your automation.
  // 'careers.example-company.com'
]);

export async function apply(packet) {
  const url = new URL(packet.job.url);
  if (!ALLOWLIST.has(url.hostname)) {
    return { status: 'review', reason: 'domain_not_allowlisted' };
  }

  const browser = await chromium.launch({ headless: true });
  const page = await browser.newPage();

  try {
    await page.goto(packet.job.url, { waitUntil: 'domcontentloaded' });
    await page.getByLabel(/full name/i).fill(packet.candidate.full_name);
    await page.getByLabel(/email/i).fill(packet.candidate.email);
    await page.getByLabel(/phone/i).fill(packet.candidate.phone);

    const resumeInput = page.locator('input[type="file"]').first();
    await resumeInput.setInputFiles(packet.files.resume);

    const body = (await page.locator('body').innerText()).toLowerCase();
    if (body.includes('captcha') || body.includes('verify you are human')) {
      return { status: 'review', reason: 'security_challenge' };
    }

    const unresolved = await findUnresolvedRequiredQuestions(page, packet);
    if (unresolved.length) {
      return { status: 'review', reason: 'unknown_required_answers', unresolved };
    }

    await page.screenshot({ path: `review-${packet.job.job_key}.png`, fullPage: true });
    if (!AUTO_SUBMIT) return { status: 'review', reason: 'final_approval_required' };

    await page.getByRole('button', { name: /submit application|apply/i }).click();
    return { status: 'submitted' };
  } catch (err) {
    return { status: 'failed', reason: String(err) };
  } finally {
    await browser.close();
  }
}

Playwright recommends user-facing locators such as getByRole() and getByLabel(), which are generally more resilient than long CSS/XPath selectors.

Do not automate around these conditions

  • STOP: CAPTCHA or "verify you are human".
  • STOP: MFA/login approval requiring a human.
  • STOP: a required question for which your approved candidate profile has no answer.
  • STOP: a domain not present in the auto-submit allowlist.
  • STOP: a job already submitted previously.
  • STOP: a mismatch between job location/work authorization requirements and your profile.

8. Recommended controls so the bot does not damage your job search

Daily capStart with 5-10 high-quality applications/day rather than hundreds.
Company cooldownAvoid submitting to multiple near-identical roles at the same employer on the same day.
Resume versionsMaintain 2-3 approved CV variants, e.g. DevOps, Cloud Infrastructure, Platform/SRE.
Truth lockQuestionnaire answers come from an approved profile database, never free-form invention.
Approval thresholdRequire manual approval for borderline matches, relocation, unusual salary, or sponsorship questions.
Audit logKeep the job URL, date, exact resume used, answers supplied, and submission result.

9. Suggested first implementation

Stage A - Discovery automation

  1. Apify task runs twice daily.
  2. n8n pulls new rows.
  3. Duplicate jobs are removed.
  4. Hard filters + CV match score run.
  5. Top matches are written to a Job Queue.

Stage B - Assisted applications

  1. n8n selects a CV version.
  2. It drafts role-specific cover text.
  3. It prepares known questionnaire answers.
  4. You receive a review card with score, missing skills, job URL and application packet.
  5. You approve or reject.

Stage C - Selective auto-submit

  1. Create an explicit domain allowlist.
  2. Implement one permitted ATS/site at a time.
  3. Run Playwright with AUTO_SUBMIT=false first and inspect screenshots.
  4. Only switch AUTO_SUBMIT=true for verified domains with no unresolved questions/security challenges.
  5. Keep LinkedIn and any other restricted source in manual mode.

12. What to build next

For a production setup, the next deliverable should be a self-contained project containing:

  • n8n/workflow.json - importable workflow
  • apply-worker/ - Node.js + Playwright service
  • config/candidate-profile.example.json - approved personal facts
  • config/job-rules.json - titles, locations, skills, score thresholds
  • config/domain-allowlist.json - permitted auto-submit domains only
  • db/schema.sql - jobs and applications tables
  • .env.example - secrets configuration, with no real secrets committed
