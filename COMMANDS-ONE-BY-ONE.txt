SIMPLE DOCKER + KUBERNETES PRACTICE: START HERE

FIRST: Install Docker and Kind (Mac: Docker Desktop + brew install kind kubectl; Windows: Docker Desktop WSL2 + ./install-linux-tools.sh; Ubuntu VM: Docker Engine + ./install-linux-tools.sh).

Then type each line in order:
./lab setup
kubectl get nodes
kubectl -n practice get pods

Every scenario: START HEALTHY -> BREAK -> FIND -> FIX -> VERIFY. Commands are one per line.


================================================================
QUESTION 1. Container stops after starting (DCK-001)
Where: Local lab

1. START HEALTHY
./lab prepare DCK-001

docker ps -a


2. BREAK
docker rm -f practice-web
docker run -d --name practice-web --label practice.simple.lab=yes practice-web:1 python -c 'import sys;sys.exit(1)'


3. FIND
docker ps -a
docker inspect practice-web --format '{{.State.ExitCode}}'
docker logs practice-web


4. FIX
docker rm -f practice-web
docker run -d --name practice-web --label practice.simple.lab=yes -p 127.0.0.1:18080:8080 practice-web:1


5. VERIFY
docker ps
curl -fsS http://127.0.0.1:18080/healthz


EXPECT: STATUS=Exited; exit code 1.
INTERVIEW: Check exit code, examine logs, then start the container with its correct application command.

QUESTION 10. Pod stuck Terminating (K8S-010)
Where: Local lab

1. START HEALTHY

2. BREAK
kubectl -n practice patch deployment web --type=strategic -p '{"spec":{"template":{"spec":{"terminationGracePeriodSeconds":120,"containers":[{"name":"web","lifecycle":{"preStop":{"exec":{"command":["sh","-c","sleep 90"]}}}}]}}}}'

kubectl -n practice get events --sort-by=.metadata.creationTimestamp

5. VERIFY
kubectl -n practice rollout status deployment/web --timeout=120s
kubectl -n practice get pods -o wide


EXPECT: A 90-second preStop hook delays termination.
INTERVIEW: Check lifecycle hooks and grace periods; wait for this isolated Pod to finish naturally.

NOTE: The old Pod may remain Terminating for up to the grace period. Do not force-delete production Pods merely because they are slow.
